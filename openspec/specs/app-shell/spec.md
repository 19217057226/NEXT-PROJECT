# app-shell

能力范围：全局布局、导航位置、主题（亮/暗）。

## 需求：手动主题控制

应用**必须**提供显式控件，用于在亮色与暗色外观之间切换。当前选择**必须**通过客户端存储（例如经 `next-themes` 使用 `localStorage`）在页面刷新与新会话间持久保存。

应用**不得**仅以与操作系统主题自动同步作为唯一机制（`enableSystem` 关闭或等价配置）。

### 场景：用户选择暗色模式

- **当** 用户通过主题控件激活暗色模式
- **那么** 文档根节点体现暗色样式（例如 `html` 上 `class="dark"`）
- **并且** Ant Design 组件使用暗色算法与一致的布局 token

### 场景：用户再次访问

- **当** 用户在新会话中再次打开站点
- **那么** 先前选择的主题被恢复，且在可接受的 SSR/水合限制下，不出现长时间错误主题的闪烁

---

## 需求：左侧主导航

站点主导航**必须**在左侧纵向区域渲染，使用 Ant Design `Layout.Sider` 与 `mode="inline"` 的 `Menu`。导航项**必须**与 `siteConfig.nav` 一致（文案与路由）。

**必须**移除「固定顶栏 + 横向菜单作为桌面唯一主导航」的旧模式。

### 场景：桌面或平板视口

- **当** 视口宽度不低于中等断点（约 768px）
- **那么** 侧栏为展开状态，每项可见文字标签
- **并且** 当前路由在视觉上显示为选中

### 场景：窄视口

- **当** 视口宽度低于中等断点
- **那么** 左侧保留始终可见的窄条（仅图标 + Tooltip 或等价方案）
- **并且** 主导航不得仅通过隐藏的汉堡抽屉访问（抽屉仅可用于次要操作）

---

## 需求：壳层样式与可读性

全局壳层在浅色模式下**应当**采用中性灰白与边框或轻分隔线区分层次。暗色模式下**应当**使用 Ant Design 暗色 token 与全局 CSS 变量，使 body 背景、默认文字与 `.post-content` 可读，避免依赖未文档化的一次性颜色。

### 场景：文章页暗色模式

- **当** 暗色模式开启
- **那么** `.post-content` 内正文与标题相对背景具有足够对比度

---

## 需求：布局集成

根布局**必须**使用与 Next.js App Router 及 Ant Design `ConfigProvider` 兼容的客户端主题 Provider 包裹应用内容。主内容区**不得**再依赖仅为 64px 固定顶栏而设的顶部偏移，除非有意保留单独的极简顶栏。

### 场景：页面结构

- **当** 任意页面在应用壳层内渲染
- **那么** 页脚与主内容位于侧栏旁的内容列中，且仅由壳层本身不引起横向溢出
