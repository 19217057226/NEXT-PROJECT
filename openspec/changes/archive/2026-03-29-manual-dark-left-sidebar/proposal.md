# 提案：手动暗夜模式 + 左侧栏（始终可见）

## 摘要

引入**由用户控制的亮色/暗色主题**（本变更不采用自动跟随系统），将主导航从顶部 Header 移至**左侧边栏**，并在各视口宽度下保持**可见**（见 `design.md` 中的移动端方案），整体走向灰白中性色与以边框为主的层次。

## 背景与问题

- 当前应用使用固定顶栏 + 横向导航，视觉栈仅为浅色（Ant Design token + `globals.css` 与页面中的硬编码颜色）。
- 尚无暗色主题；若要在更克制的灰白体系上支持夜间使用，需要统一入口切换外观。
- 左侧导航更符合常见内容/博客布局，并为阅读腾出纵向空间。

## 目标

1. **手动主题切换**：用户可在亮/暗之间切换；偏好跨访问持久化（例如 `localStorage`）。
2. **左侧栏始终展示**：主导航使用 Ant Design `Layout.Sider` + 纵向 `Menu`；在桌面/平板上不以「仅汉堡菜单」隐藏侧栏。在窄视口下**保留左侧常驻入口**（推荐：窄图标条或始终可见的细侧栏），避免导航只存在于抽屉中——具体移动端方案见 `design.md`。
3. **视觉方向**：向**灰白中性**与**边框/轻微 elevation** 分层靠拢；与整体冲突的大面积蓝色渐变 Hero 可按页面逐步收敛。

## 非目标

- 仅以操作系统 `prefers-color-scheme` 作为唯一真相来源（除非后续单独增加）。
- 一次性重绘所有页面的内联样式——优先完成壳层（布局、顶栏/侧栏、token、全局 CSS）；卡片与文章区可在后续任务中扫尾。
- 主题控件的完整国际化（中英文极简即可）。

## 验收标准

- 切换后 Ant Design 组件与主壳层在亮/暗算法间可见变化。
- 刷新页面后仍保持所选主题。
- 在典型桌面/笔记本宽度下，侧栏存在且可用，无需先打开抽屉；移动端行为与 `design.md` 约定一致。

## 风险

- 各页面**内联样式**在暗色模式下可能不协调，需逐步迁移到 token/CSS 变量。
- **`next-themes`** 与 Ant Design 的 SSR 需正确设置 `suppressHydrationWarning` 与客户端边界，以避免闪烁或水合不一致。
